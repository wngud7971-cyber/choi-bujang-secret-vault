# 보안 점검 화면 개편 명세

작성일: 2026-10-30. SpecFrame 방식으로 정리한 이번 변경의 범위와 확인 기준이다. 공식 과제에 새로운 제출 조건을 추가하는 문서가 아니다.

## 목표

기존 기능을 유지하면서 보호 현황의 세 핵심 점검을 라이트 모드의 정렬된 목록으로 보여 준다. 사용자가 점검 항목, 현재 상태, 최근 응답 시각과 다음 조작을 비교할 수 있게 한다.

## 기준과 확정된 결정

- 사용자가 제시한 Grafana·Prometheus 대시보드의 정렬과 정보 밀도를 참고한다. 라이트 모드를 유지한다.
- 핵심 기능은 16단계 오류 알림·진단, 17단계 AI 연결 점검, 20단계 설치 패키지 취약점 조회이다.
- 기능·요청 방식·입력 계약은 유지하고 학생 화면의 표시 구조와 허용된 색상만 변경한다.
- 검토용 사본에서 작업한다. main, 기존 프로젝트와 제출물을 변경하거나 옮기지 않는다.
- 기존 PC 실측·Windows 조회·업무 앱·보안 기록과 다른 학생 표시 함수는 보존한다.

## 입력과 동작 계약

| 화면 | 기존 입력 / 코드 | 이번 표시 변경 |
|---|---|---|
| 오류 알림·진단 요약 | `renderStatus` → `summarizeDiagnostics` → `publishCore` | 기존 상태·알림 요약·응답 시각을 목록의 해당 행에 표시 |
| AI 연결 요약 | `renderAiConnection` → `summarizeAi` → `publishCore` | 기존 verified·test·오류·예제의 구분을 유지해 표시 |
| 패키지 조회 요약 | `renderVulnerabilities` → `summarizePackages` → `publishCore` | 기존 미설정·부분 결과·확인 불가·완료의 구분을 유지해 표시 |
| 목록 구성 | `renderCore` / `renderOverview` | 항목, 현재 상태와 근거, 최근 응답, 확인 버튼을 같은 열에 정렬 |
| 이동 버튼 | `focusProvided` / 기존 제공 버튼 ID | 기존처럼 상세 영역을 펼치고 초점을 이동. 조회·승인을 대신 실행하지 않음 |

새 API 필드, 요청, 점검 결과 계산을 도입하지 않는다. 실제 입력이 없으면 기존 요청 전·실패·확인 불가를 유지한다. 예제 자료와 시험 연결을 실제 성공으로 표현하지 않는다.

## UI 요구사항

1. 세 기능은 진단 → AI 연결 → 취약점 조회 순서로 표시한다. 이는 읽는 순서이며 세 요청을 자동으로 연쇄 실행하는 절차가 아니다.
2. 상태와 짧은 요약은 펼치기 전에도 보인다. 상세 해석은 각 항목의 ‘결과 해석·다음 할 일’에서 확인한다.
3. 각 시각은 해당 응답에서 가져오며 KST로 표시한다. 유효한 응답 시각은 `time`의 `datetime`에도 반영한다. 재요청 중·실패·초기 상태에서는 이전 성공 시각을 새 결과처럼 남기지 않는다.
4. 목록에는 열 제목과 행 제목을 제공한다. 좁은 화면에서 기존 표 스타일의 가로 스크롤 영역을 사용하고, 이 영역은 키보드로 접근 가능해야 한다.
5. 기존 이동 버튼 이름과 `data-focus-key`, 상세 영역의 `data-preserve-key`는 유지한다. 결과 갱신으로 사용자 초점이나 펼침 상태를 임의로 바꾸지 않는다.
6. DOM은 `createElement`·`textContent`로 구성한다. 외부 폰트·이미지·UI 라이브러리·임의 CSS를 추가하지 않는다.
7. `appearance.json`의 세 색상만 조정한다. 상태색은 제공 계약을 유지하고 텍스트와 함께 구분한다.
8. 사용자 추가 요청에 따라 학생 화면은 중첩 카드 대신 평면적인 목록과 구분선으로 구성한다. 핵심 점검 외곽, 보조 관측 카드와 최근 기록 외곽을 제거하고 PC·Windows 학생 화면의 카드 클래스만 걷어 낸다. 실측 데이터, 그래프·범례·단위·오류·버튼·초점 및 제공 컨테이너는 유지한다.
9. 이어진 공통 기능 정리 요청에 따라 공통 HTML도 표시 범위에서 조정한다. 개발 출처 배지·파일·함수 표시를 없애고 기능별 결과를 같은 영역으로 묶는다. 중복 응답은 펼칠 수 있는 요약·상세로 유지하며 계정 연결·AI 승인·보안 조치를 자동 실행하지 않는다. 실제/예제/실패의 구분과 필수 버튼 이름은 유지한다.
10. 최신 사용자 요청에 따라 배경과 표면은 흰색으로 통일하고 차분한 살구빛 강조색은 유지한다. 상태 의미 색은 변경하지 않는다. 현재 화면의 도움정보 복사는 기존 공통 버튼으로 합치고 공통 버튼이 없는 환경은 독립 복사 기능을 유지한다.

## 수정 범위

| 파일 | 목적 |
|---|---|
| 이 명세 | 요구사항과 수용 기준 |
| `Design.md` | 참고 자료에서 채택한 디자인 결정과 제한 |
| `on-client/student/extension.mjs` | 핵심 점검 목록의 DOM 구성 및 시각의 의미 표시 |
| `on-client/student/appearance.json` | 흰색 배경·흰색 표면·차분한 살구빛 강조색 |
| `on-client/public/index.html` | 표시 문구·개발 출처 배지·공통 결과 그룹 정리. 기존 ID와 조작 속성 유지 |
| `on-client/student/pc-status-view.mjs` | 기능과 무관한 개발 출처 문구 정리 |
| `test/day4-ui.test.mjs` | 기존 상태 전환·초점 보존 검사에 목록 의미 구조와 시각 초기화 확인을 보완 |

제공 `public/app.js`, `public/style.css`, `src/server.mjs`, 인증·접근 판정·API는 변경하지 않는다. `public/index.html`은 최신 사용자 요청에 필요한 표시 문구·그룹 구조에 한해 조정한다. 앱 전체 외곽 레이아웃을 새 CSS로 다시 만드는 작업은 포함하지 않는다.

## 수용 기준과 확인 방법

| 기준 | 확인 방법 |
|---|---|
| 세 핵심 기능과 기존 이동 동작 유지 | 기존 UI 검사: 순서, 제공 영역 펼침·초점 이동, 요청 자동 실행 없음 |
| 기존 상태 의미 유지 | 기존 UI 검사: loading·idle·error, verified·test·demo, 패키지 부분 결과·취약점 정보 |
| 시각과 접근성 의미 구조 | 보완 검사: 행·열 제목, 스크롤 영역 접근, 유효한 datetime, 실패 후 이전 시각 제거 |
| 앞 단계 기능 보존 | 학생 함수와 요약 로직의 변경 범위 대조, 기존 PC·Windows·기록·그래프 검사 |
| 동작 코드 보존 | 공통 app.js·style.css·server.mjs의 SHA-256 비교, 변경 HTML의 기존 ID·조작 계약 대조 |
| 화면 사용성 | 사용자 직접 확인: 새로고침 → 목록 표시 → 키보드로 영역 이동 → 상세 펼침 |

자동 검사는 모의 DOM·입력을 사용한 확인이며 실제 계정 연결, 유료 AI 응답, 현재 OSV 조회 또는 브라우저 렌더링을 실행했다는 뜻이 아니다. 실행하지 않은 확인은 미확인으로 남긴다.
