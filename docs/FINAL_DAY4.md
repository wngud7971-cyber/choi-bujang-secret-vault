## 4. 다시 조회·대기·오류와 키보드

| 화면 | 다시 조회 대상 | 대기/실패 동작 |
|---|---|---|
| 보호 현황 | 기존 계정·기기·세션·업무 앱·보안 기록과 PC·Windows 조회 | ‘새로 읽는 중…’. 실패는 카드와 오류 상세에서 확인. 추가 그래픽 디자인 적용 후 각 기존 조회 함수를 병행 호출하며 DDoS 방어 연결을 설정하는 버튼이 아님. |
| 내 PC 상태 | 기존 PC 기록 복원과 CPU·메모리·C: 실측 | 실패 단계/항목·이유·다음 행동. 수동 조회 응답의 측정 시각 표시. |

버튼은 다시 그리는 결과 영역 밖의 같은 DOM 위치를 유지한다. 대기 중에는 `aria-disabled`와 클릭 처리로 중복 요청을 막고, 버튼을 제거하거나 네이티브 disabled로 바꿔 키보드 초점을 잃게 하지 않는다. ‘다시 조회’라는 보이는 이름을 포함한 항목별 접근성 이름을 붙였다. 완료·실패·대기는 안정된 상태 영역에서 알리며 결과 영역은 `aria-busy`로 구분한다.

메뉴는 Tab과 방향키·Home·End, 버튼은 기본 Enter/Space 동작으로 사용할 수 있다. 학생 요약 바로가기를 사용하면 대상 메뉴로 이동하며, 결과 갱신 중 초점이 있던 학생 바로가기는 같은 역할의 새 버튼으로 초점을 복원한다. 포커스 표시도 유지한다.

오류 안내는 ‘무엇을 읽지 못했는가 → 이유 → 다음 할 일’ 순서다. CPU·메모리·C:와 Windows 로그는 부분 실패를 각각 표시한다. 일반 권한 거부 시 관리자 실행·방화벽/보안 정책 변경을 유도하지 않는다. 기존 기록을 삭제하라고 안내하지 않는다.

PC 수집은 기존 5초 중복 방지 정책을 사용한다. 5초보다 빠른 수동 조회는 같은 실제 측정 기록을 반환할 수 있으며 새 시각을 꾸며 내지 않는다. 다시 조회에 따른 새 측정 시각을 비교할 때는 5초 이상 간격을 둔다.

- C: 막대의 보라색은 일반 사용자 가용 공간이다. 회색 나머지는 사용·예약 등 가용 공간 이외 영역이며 순수 파일 사용량으로 단정하지 않는다.

- 마지막 측정에서 15초를 초과했거나 조회가 실패했을 때: 기존 ‘과거 기록, 현재 상태로 단정할 수 없습니다’ 경고를 유지한다. 실패 이유와 다음 행동도 보존한다.
- Windows 기록은 별도 수동 조회이므로 캡처의 09:01:21 KST 기록이 09:04경 ‘이전 조회 기록’으로 보이는 것은 기존 정책에 맞다. Windows 표시/조회 코드와 5초 PC 측정 주기는 이번 수정에서 변경하지 않았다.

관련 화면 시험 10개와 PC 시험 12개, **총 22개가 통과**했다. 최초 제한된 실행 환경에서는 임시 기록 경로 접근과 로컬 통신 제한으로 기존 시험 5개가 실패했고, 일반 사용자 환경에서 같은 시험을 재실행해 모두 통과했다. 관리자 실행이나 보안 설정 변경을 하지 않았다. 실제 PC 시험은 09:23:11.797 KST와 09:23:16.875 KST에 측정했고 두 실측 간격 5,078ms 및 임시 시험 기록 2건 복원을 확인했다. 모의 문구 시험의 고정 시각/수치는 실제 PC 측정 결과가 아니다.

수정 후 사용자가 제공한 실제 브라우저 캡처에서 마지막 측정은 **2026년 10월 27일 09:29:37 KST · 0초 전**, 직전 비교 기준은 **09:29:32 KST**로 표시됐다. 최근 측정에 불필요한 ‘과거 기록’ 문구가 없으며 CPU·메모리·C:의 출처·측정 범위·단위·각 시각이 유지됐다. 캡처는 성공 상태의 표시 근거이며 조회 대기 순간이나 실패 화면을 추가 촬영한 자료는 아니다. 대기·15초 초과·실패·복구의 세부 분기는 위 자동 시험으로 확인했다. 이후 사용자는 ‘확인했어’라고 응답했다. 이번 기록 갱신에서는 앱 코드를 추가 변경하거나 시험을 재실행하지 않았다.

재현: 7절의 명령으로 기존 서버를 실행하고 `http://127.0.0.1:5189/`에서 Ctrl+F5를 누른다. 보호 현황 또는 내 PC 상태에서 자동 측정의 다음 요청을 기다리거나 ‘다시 조회’를 누른다. 최근 값은 원래 측정 시각과 조회 대기 안내를 유지하고, 성공 후 대기 안내가 사라져야 한다. 실패 확인이 필요하면 7절의 앱 서버 일시 정지 절차만 사용한다. 실패 뒤 기존 자료가 새 성공 결과처럼 보이지 않아야 한다. Windows 기록은 PC의 5초 측정과 별개로 ‘다시 조회’ 후 조회 시각을 확인한다.

## 10. 기존 방어 기능 재사용 범위 보완 · 2026년 10월 27일

사용자는 1일차의 ‘22단계 프로젝트를 실행하고 다듬을 핵심 기능 3가지 선정’ 취지에 맞춰 기존 구현을 먼저 살피도록 요청했다. 코드와 기존 실행 설명서를 대조한 뒤 `FINAL_DAY1.md`와 이 보고서 두 파일의 보완 승인을 받았다. 주제 세 가지와 기존 2~4일차 앱 기능은 보존했다.

| 구분 | 현재 기록할 수 있는 범위 |
|---|---|
| 기존 접근 통제 | 로그인·기기·자원 검사와 엔진 판정 코드가 있다. 현재 로컬 화면의 미연결과 코드 존재는 별개다. 실제 서버가 이 정책을 사용하는지는 확인해야 한다. |
| 기존 API 남용 관련 탐지 | 대량 조회 탐지와 접근 회수 제안이 있다. 요청을 제한하거나 대규모 DDoS를 차단하는 완성 기능으로 부르지 않는다. |
| 기존 계정 악용·자료 유출 XDR | 연습 경보 판정·거부 규칙·ZTNA 적용 경로가 있다. 실제 경보 공급과 보호 경로 연결·효과는 별도 미확인이다. |

| 다음 연결 점검 | 기존 SDP 서버·개인 설정의 준비 여부, 본인 범위 조회, 실제 정책·사건·집행 경로를 순서대로 확인한다. AI 연결과 SDP 연결은 별개다. |

이번 보완은 위 두 보고서의 내용만 변경했다. 앱·방어 코드·실행 옵션·DB·개인 자격·보안 설정·기존 제출물은 변경하지 않았다. 코드와 문서 경로를 대조했으며 기존 시험을 재실행하거나 원격 저장소/배포·실제 방어 연결을 새로 검증하지 않았다. 기존 시험 결과는 당시 실행 기록으로 유지한다. 실행 명령과 화면 확인 순서는 7절과 같고, 보고서 보완을 위해 서버를 다시 시작할 필요는 없다.
