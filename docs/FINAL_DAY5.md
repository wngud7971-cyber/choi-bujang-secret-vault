# 5일차 확인 기록

2026-10-30 · 현재 작업 사본: `verification/alekov-0.2.21-merge-review`

사용 안내서는 `docs/USER_GUIDE.md`에 작성했다. 실행 폴더와 명령, 진단·AI 연결·취약점 조회 사용법, 오류 확인, 종료·재실행 방법을 담았다.

## 이번에 확인한 것

사용자가 새 PowerShell 창에서 안내한 다섯 줄을 실행한 뒤 앱이 열린다고 확인했다. 실행 도구는 `on-client/tools/start-alekov.ps1`, 접속 주소는 `http://127.0.0.1:5197/`이다. 앱이 열린 것은 사용자 확인 결과이며, AI가 브라우저에서 새로 실행해 검증한 결과는 아니다.

처음에는 다음 세 곳에서 막혔고 안내를 고쳤다.

| 막힌 부분 | 반영한 내용 |
|---|---|
| 설명 문장인 ‘작성: …’를 PowerShell에 입력함 | 명령 상자 안의 다섯 줄만 복사하도록 표시하고 작성 문장은 사용 안내에서 삭제 |
| 기존 검토용 앱이 5197번을 사용 중 | 새 서버 실행이 아니라는 점을 안내. 기존 앱 종료 후 같은 포트로 다시 실행하도록 정리 |
| 새 창의 위치가 사용자 홈이라 실행 파일을 찾지 못함 | 폴더 이동을 포함한 다섯 줄 전체를 실행하도록 수정. 이후 사용자가 앱 열림 확인 |

다섯 줄의 경로와 PowerShell 문법은 소스로 대조했다. 패키지 조회 설정은 원본 `step22-main`의 설치 폴더를 사용한다. 이번 재실행에서 진단 복사·AI 모델 응답·OSV 조회·PC 기록 유지까지 다시 시험했다고 기록하지 않는다.

## 재현 확인 범위

기존 5일차 체크리스트(`FINAL_DAY1.md`의 5-2·5-3)는 다른 사람이 안내만 보고 실행하거나 같은 PC의 다른 폴더에서 재현하고, 막힌 안내를 고친 뒤 다시 실행하는 확인을 포함한다.

처음에는 현재 작업 사본에서만 재실행을 확인했다. 이후 아래 별도 폴더를 준비했고, 사용자가 ‘되는 거 확인했어’라고 앱 실행 결과를 확인했다. 최신 수정본의 같은 PC·다른 폴더 실행을 사용자 확인으로 기록한다. 과거 버전의 재현을 이번 결과로 대신하지 않는다. 현재 상태는 **안내서 작성·막힘 보완·현재 폴더 재실행·같은 PC 별도 폴더 실행 확인 완료**이다.

앱 코드·원본 프로젝트·main·기존 제출물은 이번 문서 반영에서 변경하지 않았다.

## 별도 폴더 준비

사용자 요청에 따라 `verification/day5-20261030-ui`를 새로 준비했다. 소스·문서 273개를 복사하고 복사 당시 SHA-256 일치를 확인했다. 기존 `.local` 기록, 로그인 설정, `node_modules` 연결, 비공개 파일과 빌드·복구 산출물은 복사하지 않았다. 원본 파일은 이동하거나 삭제하지 않았다.

사본의 `docs/USER_GUIDE.md`는 실행 폴더 예시를 새 사본의 `on-client` 경로로 바꿨다. 런타임 소스는 원본과 같으며 패키지 조회는 안내대로 기존 원본의 설치 폴더를 사용한다. 이는 같은 PC의 다른 소스 폴더 재현이며 별도 PC의 패키지 설치 검증은 아니다.

이 사본의 실행 명령과 5197번 주소를 안내한 뒤 사용자가 앱이 동작한다고 확인했다. AI가 직접 화면에서 관찰한 결과는 아니다. 이 사본의 종료 후 재시작, 과거 기록 복원, 새 AI 승인·모델 응답·OSV 조회까지 확인했다고 확대하지 않는다. 새 폴더의 계정 연결 설정은 실행 도구가 별도로 준비하며 기존 AI 승인 성공을 새 폴더의 현재 결과로 간주하지 않는다.
