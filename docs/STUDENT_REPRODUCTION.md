## 2. 원본 보존과 새 빈 폴더에서의 재현

기존 작업 폴더·브랜치·미커밋 변경·인증 설정은 보존합니다. 기존 폴더를 복사해 재현하지 않고 **Git에 기록된 해당 커밋만** clone합니다. node_modules·실제 .env·개인 설정·인증서·Vault·DB·캐시를 원본에서 복사하지 않습니다.

아래는 다른 PC에서도 쓸 수 있는 절차입니다. 기존 저장소 **밖의 부모 폴더**에서 새 PowerShell을 엽니다. `keshev-repro`는 아직 존재하지 않는 새 폴더 이름이어야 합니다. 이름이 이미 있으면 다른 새 이름을 사용합니다.

```powershell
node --version
git --version
$repoUrl = 'https://github.com/wngud7971-cyber/choi-bujang-secret-vault'
$releaseBranch = 'codex/step22-review'
$targetCommit = Read-Host '제출할 실제 40자리 커밋'
if ($targetCommit -notmatch '^[0-9a-f]{40}$') { throw '40자리 커밋을 확인하세요.' }
git clone --no-checkout --single-branch --branch $releaseBranch $repoUrl keshev-repro
if ($LASTEXITCODE -ne 0) { throw 'clone 실패. 기존 폴더를 지우지 말고 새 폴더와 연결 상태를 확인하세요.' }
Set-Location -LiteralPath .\keshev-repro
git checkout --detach $targetCommit
if ($LASTEXITCODE -ne 0) { throw '선택한 커밋을 확인하지 못했습니다.' }
git rev-parse HEAD
git status --short
git rev-parse HEAD:on-client
```

HEAD는 입력한 40자리와 같고, 시작 시 작업 상태는 깨끗해야 합니다. 이 PC에서 만든 새 재현 폴더와 명령 출력은 별도로 기록합니다. 문서의 개인 PC 절대경로는 위치 설명용일 뿐 실행의 필수 설정이 아닙니다. clone된 폴더를 기준으로 다음을 실행합니다.

```powershell
Set-Location -LiteralPath .\on-client
node --check .\student\extension.mjs
node .\src\server.mjs
```

Node.js v24.19.0으로 확인합니다. 제공 실행 도구는 22~24를 허용하지만 다른 버전의 전체 재현은 미확인입니다. 이 앱에는 외부 npm 의존성과 package-lock.json이 없어 추가 npm 설치 단계가 없습니다. 이 검토 브랜치에는 루트 package.json·lock이 없고, main에 보존한 과거 프로젝트의 설치 절차와 섞지 않습니다. `npm`이 없는 환경에서도 위 Node 명령을 사용합니다. 포트가 비어 있고 ON_PORT가 미설정이면 주소는 **http://127.0.0.1:5189/** 입니다.

기본 로그 `케셰브 연결 확인: http://127.0.0.1:5189` 뒤 브라우저에서 주소를 엽니다. 「보호 현황」과 학생 표시 영역을 확인합니다. 실제 설정이 없는 기본 실행에서 `ENGINE_NOT_CONNECTED`·연결 없음은 예상된 상태이며 로그인 성공이 아닙니다. 시작 로그와 정적 HTTP 200은 실제 시스템 연결 성공을 뜻하지 않습니다.

포트 충돌 시 기존 프로그램을 종료하지 않습니다. 새 서버에만 `$env:ON_PORT = '5190'`처럼 다른 포트를 지정하고 브라우저 주소도 맞춥니다. 이번 자동 재현은 기존 서버를 보존하기 위해 빈 임시 포트를 사용하고 실제 포트를 실행 로그에 기록합니다.

종료는 서버를 시작한 창에서 Ctrl+C 후 새 요청의 연결 실패를 확인하고, 같은 폴더에서 같은 명령으로 재실행합니다. 이번 도구 실행은 도구가 시작한 자식 서버만 종료해 확인했으며 사용자가 새 창에서 직접 Ctrl+C를 수행한 사실로 쓰지 않습니다.

demo는 기본 서버를 먼저 종료한 후 같은 폴더에서 `node .\src\server.mjs --demo`로 실행합니다. 예제 사용자·앱·기록만 제공됩니다. 종료·재실행·버튼·키보드 설명은 [21단계 실행 설명서](STUDENT_RUNBOOK.md)를 함께 봅니다. 설정 견본은 [on-client/.env.example](../on-client/.env.example)이며 자동 로드되지 않습니다. 실제 운영 설정을 임의로 만들지 않습니다.

이번에 확인하는 백업·복원은 **학생 소스 ZIP을 새 폴더에 복원한 파일 일치**입니다. 원천 DB·운영 데이터·실제 조치 이력 복구 성공으로 표시하지 않습니다. 코드 롤백도 원천에서 이미 실행한 보안 조치를 되돌리지 않습니다.

## 5. 지원 범위·남은 작업·인수인계

- 현재 학생 릴리스는 검증 중인 버전입니다. 실제 운영 인증·실제 보안 집행·v1.0 자동 인증을 완료했다고 쓰지 않습니다.
- Windows win32/x64·Node.js 24.19.0으로 로컬 앱을 확인합니다. 다른 OS·다른 Node 버전·운영 native 호스트 이전은 미확인입니다.
- 기본·demo 실행은 실제 연결과 구분합니다. AI 모델 응답·AI 사건 설명·조치 효과·외부 OSV 조회를 서로 대신하는 성공 증거로 쓰지 않습니다.
- 원문 AI 판정은 서버가 읽은 일관성 평가이며 명령 실행·운영 안전 인증이 아닙니다. 22단계 공식 통과 여부는 제출 후 서버에서 확인합니다.
- 인수인계할 파일은 저장소의 해당 커밋, README, 학생 실행 설명서, 이 재현 기록, 버전 JSON, 비밀값 없는 설정 견본입니다. 실제 비밀값과 원천 데이터는 일반 인수인계 ZIP에 넣지 않습니다.

추가 확인은 사용자가 새 PowerShell에서 위 절차의 해당 커밋을 받는 것부터 한 번에 하나씩 진행합니다. 운영 연결 준비가 안 된 항목은 준비 후 별도 회차·커밋으로 확인하고, 그때도 이전 모의 결과를 실제 운영 성공으로 바꾸어 적지 않습니다.

## 6. 커밋·원문 제출

이 자료와 실행 코드를 같은 커밋에 둔 후 실제 40자리 커밋을 과제 화면에 직접 입력합니다. 비공개 저장소는 공개로 바꾸지 않습니다. 필요한 경우 해당 단계의 최신 원문 전달 도구를 프로젝트 밖에 풀어 **새 clone의 Git 최상위**에서 다음 형태로 실행합니다.

```powershell
$submitCommit = (git rev-parse HEAD).Trim()
node '프로젝트 밖의 실제 도구 경로\student-source-cli.mjs' --commit $submitCommit --output '프로젝트 밖의 새 출력 경로\alekov-source.json'
```

위 두 경로는 실제 설치 위치와 미리 만든 출력 폴더로 바꿉니다. 이 PC에서 확인한 기존 도구 위치는 원래 작업 폴더의 형제인 submission-tools/alekov-source-tool/student-source-cli.mjs이며 포털 최신 도구와 동일한지는 미확인입니다. 도구는 커밋 원문만 묶고 학생 코드 실행·업로드·과제 제출을 하지 않습니다. 생성 JSON은 동일 저장소·커밋·22단계에 선택합니다. 전달 완료와 공식 통과는 구분합니다.
