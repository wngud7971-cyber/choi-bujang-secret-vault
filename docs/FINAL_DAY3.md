## 3. 실제 조회 경로와 해석

브라우저 → `POST /api/connection-status/read`(본문 `{}`) → `on-client/src/connection-status.mjs` → Windows PowerShell 5.1의 고정된 조회 명령 → 검증된 결과만 화면에 표시한다. 값별 조회 시각과 출처, 이벤트 집계 시작·끝 시각은 KST로 표시한다.

| 항목 | 실제 조회 출처 | 표시 범위·주의 |

**Windows 경고·오류 건수는 침해나 공격 탐지 결과가 아니다.** 0건은 PC가 안전하다는 뜻이 아니다. Level 1(위험)·정보 로그·Security 로그·외부 PC는 이번 경고/오류 집계에 포함하지 않는다. 로그 삭제·보관 기간 등에 의해 사라진 사건은 복원하거나 추정하지 않는다.

이벤트 필터의 끝 시각은 조회 시작 때 고정한다. 조회가 끝난 뒤 발생한 사건은 다음 조회에 포함되므로 이벤트 뷰어와 비교할 때 동일한 시작·끝 시각을 사용한다. 전체 조회에 성공한 로그만 숫자를 표시한다. 조회 건수를 임의 상한으로 잘라 전체 건수처럼 표시하지 않는다.

## 4. 실패와 실측/예제 구분

- 일반 사용자 권한 거부·명령 미지원·시간 초과·결과 형식 오류는 **확인 불가**와 이유로 표시한다. 관리자 권한으로 재실행하거나 정책·서비스·방화벽을 변경하지 않는다.
- 네트워크 연결 상태는 읽혔지만 IP 구성을 읽지 못하면 해당 구성만 확인 불가로 남긴다.
- 로그 하나가 실패해도 다른 로그의 성공 결과는 유지한다. 실패한 건수는 `null`이며 ‘0건’으로 바꾸지 않는다.
- 읽기 가능한 활성 로그에 대해 조건에 맞는 사건이 없다는 Windows 응답을 확인한 경우만 0건으로 표시한다.
- 수동 갱신 실패 시 이전 조회 결과에 ‘이전 조회 기록’을 표시하며 현재 정상값으로 취급하지 않는다. 각 표에는 원래 조회 시각이 남는다.
- 실제 SDP가 설정되지 않았거나 예제 보안 엔진이면 **SDP 미연결**이다. 검증된 SDP 조회 경로가 없거나 응답 확인 실패면 **SDP 연결 확인 불가**다.
- 앱에 설명용 숫자·예제 기록을 채우지 않았다. 시험에 쓰는 `192.0.2.*` 주소와 경고/오류 수치는 시험 파일의 모의 자료이며 실제 조회 근거가 아니다.

필수 결과의 사용자 표시 확인까지 완료했다. 수동 재조회 버튼을 직접 눌러 시각이 바뀌는지, Windows 설정/이벤트 뷰어와 같은 시각에 수치를 비교했는지는 별도의 사용자 확인 결과가 제공되지 않아 완료로 기록하지 않는다. 해당 추가 확인 방법은 아래에 남긴다.

## 8. 같은 결과를 만드는 순서

1. 기존 앱을 실행한 PowerShell에서 Ctrl+C로 종료한다. 다른 프로젝트나 프로세스는 종료하지 않는다.
2. 다음 명령을 **한 번만** 실행한다. 앞의 `PS C:\Users\82109>` 프롬프트는 복사하지 않는다.

~~~powershell
& 'C:\Users\82109\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' 'C:\Users\82109\Documents\ChatGPT\hackert0n\step22-main\on-client\src\server.mjs'
~~~

3. `http://127.0.0.1:5189/`에서 Ctrl+F5 후 왼쪽 **연결과 기록**을 누른다. 진입 시 한 번 조회한다. Windows 초기 조회는 시간이 걸릴 수 있다.
4. 네트워크 표에서 연결 상태와 구성, 출처·조회 시각을 확인한다. Windows 설정의 네트워크 속성과 가까운 시각에 비교한다. 인터넷·SDP 연결 성공으로 확대 해석하지 않는다.
5. 방화벽 프로필별 설정과 적용 여부를 읽는다. 비교가 필요하면 Windows 보안 → 방화벽 및 네트워크 보호에서 상태만 확인하고 변경 버튼은 누르지 않는다. 읽을 수 없는 항목은 그대로 확인 불가여야 한다.
6. 이벤트 표에서 System·Application별 경고·오류의 ‘건’ 단위와 집계 기간을 확인한다. 이벤트 뷰어 → Windows 로그의 System/Application에서 같은 시작·끝 시각과 경고/오류 필터로 비교한다. Security 로그나 관리자 실행은 필요 없다.
7. **침해나 공격 탐지 결과가 아님** 문구와 별도 **SDP 미연결/확인 불가/연결 확인됨** 표시를 확인한다. 현재 실제 SDP 설정이 없으면 미연결이 예상 결과다.
8. **연결 정보 조회**를 누르면 시각과 집계 범위가 갱신된다. 화면을 그대로 두었을 때 5초마다 새 Windows 조회가 발생하지 않아야 한다. 내 PC 상태의 5초 갱신은 해당 화면에서만 기존대로 유지된다.
9. 오류가 나면 표시된 이유를 확인한다. 관리자 권한을 사용하거나 방화벽·로그·보안 설정을 바꾸지 않는다. 기존 폴더와 제출물을 삭제하거나 새 프로젝트를 만들 필요가 없다.

정상 결과는 항목별 실제 결과 또는 사유가 있는 확인 불가, 명확한 출처·시각·단위와 별도 SDP 상태다. 허용하지 않아야 할 요청은 임의 명령/경로/로그를 추가한 조회 요청이나 로컬 화면 출처가 없는 조회 요청이다. 이런 입력 처리는 내부 모의/로컬 계약 시험으로 확인하며 공격·침투나 외부 대상 시험을 하지 않는다.

시험 재실행은 기존 프로젝트 폴더에서 다음 명령을 사용한다.

~~~powershell
& 'C:\Users\82109\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --test .\test\connection-status.test.mjs .\test\pc-status.test.mjs
~~~
