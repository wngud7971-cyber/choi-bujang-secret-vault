# 12단계 · 실제 요청 확인 절차

가린 기록은 `STEP12_EVIDENCE.json`, 읽기 API는 `/api/operations`, 화면은 `/operations.html`입니다. 같은 `stageChecks` 배열에서 화면 행과 수치를 계산합니다. 공개 관측은 `probes`에 따로 있으며 각각 서버 요청 ID와 UTC 확인 시각이 있습니다. UI는 한국 시간으로 변환합니다. HTTP 성공 자체는 방어 통과가 아니며 기대와 일치하는지도 검사합니다. 공식 41종은 목록·계약과 심판 결과가 없으므로 미실행입니다.

## 자동 관측

1. `git log -1 --oneline`, `/aleph.json`의 단계·커밋·주소를 대조합니다.
2. `npm run operations:check`로 실제 공개 GET/HEAD를 실행합니다. 네트워크 실패는 미실행, 배포 불일치는 실측 불일치입니다.
3. `STEP12_EVIDENCE.json`에서 HTTP·요청 ID·시각을 확인합니다. 서버 ID 미제공은 `null`입니다. 메모 본문이나 전체 응답을 붙여넣지 않습니다.
4. 파일을 검토·커밋·배포하고 작전실의 **가린 서버 기록 JSON**과 표를 대조합니다. **서버 기록 다시 읽기**는 같은 저장 기록의 재조회입니다.

## 정상·금지 요청 실측

아래는 기존 기능을 대표하는 절차이며 공식 41종 목록이 아닙니다. 실제 운영 시험은 가상 시험 계정·메모만 사용합니다. 로그인/인증기는 공식 입력 화면에서 직접 사용합니다. 토큰·개인키를 채팅이나 기록으로 복사하지 않습니다. 브라우저 Network의 해당 요청에서 상태·서버 `x-vercel-id`·확인 시각만 대조하고, API 응답 본문에 자료가 포함되면 원문을 저장하지 않습니다. 현재 자동 관측은 인증이나 쓰기를 수행하지 않으므로 그 항목은 미실행 상태입니다.

| 단계 | 정상 요청·기대 | 금지 요청·기대 | 현재 근거 |
|---|---|---|---|
| 1 | `GET /` 자료실 화면 200 | `GET /data.json` 메모 0건·이전 표시 없음 | 공개 GET 실측 |
| 2 | 승인 기기 `GET /api/notes` 본인 목록 200 | 무인증 동일 경로 401/403 | 금지 GET만 실측 |
| 3 | 승인 기기 `POST /api/notes` 가상 메모 201 | 위조 로그인 `GET /api/notes` 401/403 | 금지 GET만 실측 |
| 4 | A 본인 단건 GET/PUT/DELETE 허용 | 승인된 B의 A 단건 GET/PUT/DELETE 404 | 양쪽 운영 미실행 |
| 5 | 보호 API 경유 본인 조회 허용 | 브라우저의 원본 DB 직접 조회 거부 | 운영 미실행 |
| 6 | 엔진 검증 등록 기기 요청 allow | 미등록 기기 요청 deny | 운영 미실행·가상 연습과 구분 |
| 7 | 정상 및 검증된 추가 확인 allow | 복합 위험 step_up | 운영 미실행·가상 연습과 구분 |
| 8 | 본인 구역 허용 | 다른 구역 및 공지 쓰기 거부 | 운영 미실행 |
| 9 | 정상 사건 observe 및 정상 연결 유지 | 탐지 사건 전달 → 회수 → 같은 신원 재전송 거부 | 운영 엔진 연결 미확인 |
| 10 | B 지정 한 건 복구·본인 조회 정상 | 복구 직후 다른 구역 조회 거부 | 운영 쓰기 미실행 |
| 11 | 현재 승인 기기 서명 요청 200 | `/api/device?approved=true` 400/401/403 | 금지 쿼리 GET만 실측·무서명 시험과 다름 |

학생은 승인 기기로 본인 메모 생성→조회→수정→삭제→로그아웃 순서의 정상 요청을 먼저 확인합니다. 이후 두 가상 계정의 소유자 경계·무서명 변경·구역 밖 조회를 확인합니다. 공격 계정의 실패만으로 정상 사용자의 접근까지 통과했다고 쓰지 않습니다. 회수 시험은 운영자 승인 및 실제 엔진 사건/회수 근거가 있어야 합니다. 10단계 복구가 200이어도 회수 신원이나 다른 구역을 허용하면 안 됩니다. 복구 전에 다른 메모·감사 기록의 보존도 확인합니다.

자동 관측기에 인증·쓰기 시험을 임의로 추가하지 않습니다. 해당 결과를 연결할 때는 공식 요청 계약과 실행 주체·실행 범위를 먼저 확인하고, 실제 API/엔진의 가린 결과에서만 행을 갱신합니다. 화면의 성공 문구, 로컬 가상 시험, 기대값만으로 행을 `observed`로 바꾸지 않습니다. 비밀번호·토큰·개인키·가명 신원 원문·메모 본문은 기록하지 않습니다.

## 연속 총공세

같은 배포 커밋을 확인한 뒤 순서대로 측정합니다: 무인증 조회 → 승인된 다른 계정의 메모 조회 / 미등록 기기 → 회수된 신원 재전송 / B 한 건 복구 → 무서명 변경 → 구역 밖 조회. 각 거부 후 정상 승인 기기의 본인 조회를 다시 실행해야 정상 사용자 과차단 여부도 확인됩니다. 이 연속 시험은 현재 미실행이며 공식 심판 결과를 대신하지 않습니다.
