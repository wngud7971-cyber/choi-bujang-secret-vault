## 정책

공개된 정책 코드 사본 `recovery/policy-baseline/decider.mjs`의 SHA-256은 `fe68d4c4e039466cea2bf739de7669692655f3da5422ce662c25575c312250a6`입니다. 이 코드에 메모 자료는 없습니다. 준비 도구는 파일을 다시 읽어 고정 해시와 대조하며 기존 시험 편집을 보존합니다. 실제 비교와 복원은 `private/recovery/test-policy/decider.mjs`에 한정합니다. `--confirm`에 미리보기의 현재 해시를 넣어야 실행되며 다른 값·오염 사본이면 중단합니다. 감사 파일은 추가만 합니다.

`.gitattributes`는 이 정책 사본 한 파일에만 `-text`를 적용하여 Git 체크아웃·ZIP 생성 시 원본 줄바꿈 바이트와 고정 SHA-256을 보존합니다. 다른 소스 파일의 줄바꿈 설정은 바꾸지 않습니다.

## 메모 백업

기존 학습 DB에 `STEP10_DATABASE.sql`을 한 번 적용해야 합니다. 새 비공개 저장소는 `training_note_recovery_backups`, 감사 저장소는 `training_note_recovery_audit`입니다. 기존 테이블의 정책이나 행을 전체 교체하지 않습니다. RLS와 ACL로 직접 클라이언트/서버 역할 접근을 막고 아래 서버 전용 함수만 허용합니다.

| 함수 | 역할 |
|---|---|
| `create_training_note_with_backup(uuid,uuid,uuid,text,text)` | B의 새 가상 메모와 사본을 같은 트랜잭션에 저장, 다시 읽어 검증 |
| `inspect_training_note_backup(uuid,uuid,uuid)` | ID·소유자·시험 실행 ID·내용 해시 확인, 메타데이터만 반환 |
| `restore_training_note(uuid,uuid,uuid,text)` | 잠근 사본 재검증 후 그 한 건만 복구, 결과 검증·감사 추가 |

서버가 검증한 시험 B만 백업 대상입니다. 일반 학생이나 A의 메모는 이 저장소에 복사하지 않습니다. 사전 사본이 없는 메모는 복구하지 않습니다. 재시도 생성은 사본을 덮어쓰지 않습니다. 변조된 원본을 새 백업으로 승격하지 않습니다.

## HTTP

서비스 `notes`, `POST /api/restore`, JSON `{ "id": "대상 UUID" }`. `noteId`는 별칭입니다. 단일 ID만 받으며 역할·소유자·본문·백업 버전·다중 ID는 입력으로 신뢰하지 않습니다. 검증된 B JWT의 `userId`와 `runId`로 사본을 선택합니다. 계정/실행이 다른 사본은 404입니다.

선택 항목 `preview: true`는 ID·소유자·내용 해시·서비스·경로만 반환합니다. 실제 복원 응답도 원문 없이 해당 메타데이터와 `restored: true`를 반환합니다. SHA-256은 UTF-8 제목 + 0 바이트 + UTF-8 내용에 적용합니다. 저장된 해시 불일치·다른 소유자의 ID 재사용은 409로 중단합니다. 미설정 저장소는 503입니다. 익명/위조는 401, 학생/A는 403, 다른 메서드는 405입니다.

일반 자료 API·Auth 발급자·DB의 소유자 조건·기기·추가 확인·XDR·탐지는 기존대로 유지합니다. 엔진은 정확한 POST 복구 경로만 기기·추가 확인 검사 뒤 전달하고 최종 API가 B/소유자/실행을 검사합니다. 기존 요청 18항목·응답 5항목에 새 신원/역할 필드를 만들지 않습니다.

## 시험과 운영

`npm run recovery:test`는 실제 PostgreSQL SQL과 실제 API 핸들러를 임시 DB·일시 서명 키로 시험합니다. 다른 메모·감사 기록 보존, 변조/삭제 복원, 누락/오염/타 소유자/다른 실행 거부와 복구 직후 대표 방어를 검증합니다. 출력에는 시나리오 이름·개수·성공 여부만 포함합니다. PGlite는 개발 의존성이며 배포 API 의존성이 아닙니다.

전체 순서는 README에 있습니다. 운영 SQL 적용·업로드·배포 Ready·운영 시험 B 복구·실제 엔진/회수·심판 판정은 로컬 시험으로 완료 처리하지 않습니다. `npm run bundle`은 로컬 결과와 읽기 전용 배포 점검을 기록하고, `--offline`은 배포 요청 없이 운영 항목을 미실행으로 기록합니다.
